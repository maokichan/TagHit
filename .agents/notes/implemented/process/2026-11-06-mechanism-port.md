# 决策：仓库治理——文档门控三守卫与决策笔记模型移植

Status: implemented

## Problem

本仓库的文档纪律——入口只放指针、细节下沉小节、路径一律仓库相对、进度与待办各有唯一归属——此前全靠手写自觉。自觉守不住四类事故：本机绝对路径漏进共享文档，下一届 agent 会把它读进去当真甚至照着执行；密钥入库即泄露；文档无限膨胀让渐进披露退化成全量阅读；被引用的事实变了而引用它的文档没动，脱钩无人察觉。
治理机制在 TuRead / Cross-Patch 已实战成型，要做的不是发明，是移植后按本地事实裁剪——哪些机械可判即拦、哪些只把"该看一眼"固定在提交时刻、哪些干脆不做。这套取舍在决策基线 D49 行只压成了一行结论，论证层由本篇承载（本目录的首篇）。

## Decision

治理件住在 `ops/`，与 `scripts/` 业务脚本分治——守卫的对象是仓库本身（路径形态、密钥、行数、引用方向），混进业务脚本会让"什么在看守仓库"失去边界。三守卫共用一个形状：零依赖 Node ESM、报错自带修法、各带不挡提交的体检模式——挡而不给修法，只会训练人去绕过。

门控点固定在 pre-commit，`set -e` 串联（[ops/scripts/docIndex.mjs](../../../../ops/scripts/docIndex.mjs) → [ops/scripts/repoGuard.mjs](../../../../ops/scripts/repoGuard.mjs) → [ops/scripts/docGuard.mjs](../../../../ops/scripts/docGuard.mjs)），每次提交必过。拦与不拦按可判定性分档：md 链接向上祖先或出仓是机械可判的导航语义错误，拦；
被引用文件进了暂存区而引用它的文档没动，只提醒——机制不保证同步、不校验语义，它只让"该看一眼"无处遁形；已知根段开头而解析失败的提及进 check 模式 notice，是失效引用探针。跟踪边的落法取字面：**有路径就算跟踪**——文档内任何路径形提及都是边，多记的边最多换来一次提醒，漏记的边丢掉一次真漂移，过近似是安全方向。

行数门控取紧：入口类硬上限 80、其余默认 300，超限 = 洗——对照代码删形容词与推演，只留判定、事实与接口形状。钩子随 `.githooks/` 入版本管理、`core.hooksPath` 激活：住在 [.git/hooks](../../../../.git/hooks) 的钩子不随 clone 分发、不被提交审查，不是仓库的一部分；激活后旧位失效，pre-push 的 `npm run ci` 同迁，守卫链只剩一处真相。
存量真实盘符形态改写为 `<盘>` / `<工作区根>` / `<仓库根>` 占位——在那几处文档里路径形态本来就是讨论对象，占位符语义保真且不给守卫开口子。`--no-verify` 是人类的绕行特权，agent 不用——门控为纪律而设，不是安全机制。

提取器的首字符类不含点，点前缀路径（`.agents/`、`.githooks/`——后者同入已知根段）按「解析失败且匹配位置前一字符是点则并入重试」兜底，否则该形态整体静默漏检（首次实害 = DECISIONS 行尾笔记回链全部死边）；方向判据从严：向上的指针一概非法，根层单件（AGENTS/TODO/README）也不例外，跨子树与全局件的指认用路径提及形态。

同一轮移植的另一半是决策笔记模型（本目录机制）：彼时的决策基线（现已退役，现行裁决事实住所属能力文档）保持一行一条的现状基线，论证层（Problem / Alternatives / Consequences）下沉到笔记；路径即元数据，生命周期、类别、提出日期编码在目录与文件名里，不设集中索引；
**Alternatives considered 强制**——记录决策而不记录它战胜了什么，等于邀请重新翻案；**笔记永不改写成另一个决定**——另起一篇，新旧互链。

## Alternatives considered

- **Cross-Patch 的 Python stdlib 形态**：TagHit 全链是 Node 工具链，mjs 形态取 TuRead 实现后与参照实现同源，审阅时可逐行对照；为三段小脚本引入第二种运行时，没有机制增益可换。
- **显式「跟踪：」行语法**（Cross-Patch 版）：要求逐条显式登记跟踪边。重复登记是负担，且未声明的路径提及（裸路径、代码块内工具路径）会静默漏出跟踪面——显式语法输给字面落法的完备性。
- **入口文档上限沿用 TuRead 的 100**：根层入口文档现存 72 行，已占 80 硬上限的九成；放宽到 100 等于给入口文档留出近三十行膨胀余量。渐进披露的命脉取紧不取松，80 更严且够用。
- **身份门控（Worked-by 溯源，两参照都有）**：单人单库，每次提交的溯源答案恒同——信息量为零，仪式成本为实。经开发者裁定不采纳；多人协作成为现实时可另起提案。
- **存量绝对路径加白名单豁免**：豁免清单是漏洞面——每条目让一类真实绝对路径永久通行，且条目只增不删、理由先于条目过期，随时间腐化。改写为占位符词表后，守卫保持零豁免。

## Consequences

所得：路径泄漏、密钥入库、文档膨胀、文档与现实脱钩各有一个机械检出口，纪律从手写自觉变成提交时的机器约束；守卫链随 clone 分发、随提交被审查，不再依赖某台机器的 [.git/hooks](../../../../.git/hooks) 孤本；失效引用探针给了脱钩第一个自动观测点；
漂移提醒首次实战即抓到真漂移（已知根段增补 `.agents/` 后，[ops/AGENTS.md](../../../../ops/AGENTS.md) 引用的根段清单漏同步被提醒逮住），证明提醒面抓的是真漂移不是噪声。

代价：根层入口文档行数余量见底，只许降不许涨——往里加内容的先决条件是先洗；守卫是正则机检，绝对路径、密钥八类、行数都存在理论误报面，误报的出口是占位符改写与体检报告人工核对，不是放宽规则；每次提交多跑三段 node，提交延迟是纪律的定价。
