# 决策：插件管理页与自开页——呈现权分离

Status: implemented

## Problem

D46 的"插件详情页"（宿主渲染的词条式全页）落地后暴露呈现权归属问题：插件的详细页本质是插件自己的内容面，宿主渲染等于为每个插件维护一套词条 UI，与首插件裁决"呈现层产物跟插件走"的归属判据相悖；同时部分插件（正在播放这类常驻控制面）需要自己的全页，通路却不存在——contentTab 槽只在功能组件侧有先例，三方怎么进、入口在哪、停用怎么收，都未裁。"插件详细页"一词混着两层东西，要拆开。修订裁决在 `docs/DECISIONS.md` D47 行，被修订的前案见 `.agents/notes/implemented/product/2026-11-01-plugin-management-surface.md`（其 ① 的全页词条形状由本篇取代）。

## Decision

"插件详细页"拆成两层、**呈现权分离**：

**① 管理页** = 插件功能组件的**全页呈现**（contentTab 槽 + 面板角标，D22 入口唯一）：进入后管理全部已安装插件；每个插件的呈现**经宿主组件**（身份事实/贡献面清单/启停/manifest.settings 经 SchemaControl）——**即便插件没有自开页，这套宿主呈现也必要存在**（声明制配置的默认归宿；插件自绘设置 UI 仍然禁止）。

**② 自开页** = 特定插件的详细页：从管理页点开、**新建标签页**；插件在 manifest 自行声明（mounts 含 contentTab）+ 入口模块具名导出 `page` 组件（loader 绑定 fullPage）——壳**不新增贡献槽**，复用 contentTab 机制（壳持标签项/单实例/D22 全页外壳/FeatureBoundary 错误隔离），**内容与交互完全归插件**，壳只提供容器。

纪律延伸：自开页入口由管理页显形、用户点开，插件不自行弹页（"不能悄悄接管"）；停用 = 贡献摘除（已开的自开页标签随停用失效，与命令清扫同款）。D46 的 `/plugin/:id` 宿主词条页撤除——其内容并入管理页 per-plugin 分区，宿主渲染的 per-plugin 独立页在本模型中无位；面板入口清单仅官方（去自开页插件在面板内的重复呈现）。首个自开页消费方 = audio-cover-player「正在播放」页（全局播放的常驻控制面：黑胶 + 传输 + 歌词跟随当前播放，无播放给空态）。

## Alternatives considered

- **D46 的宿主词条页（/plugin/:id）**：输在呈现权错位——插件的详细内容面由宿主渲染，宿主要为每个插件维护词条 UI，插件一更新宿主就得追赶；与"数据层产物跟宿主能力走、呈现层产物跟插件走"的归属判据直接冲突（呈现归插件）。撤除，内容并入管理页 per-plugin 分区。
- **壳新增自开页专用贡献槽**：输在 contentTab 的机制件齐全（壳持标签项/单实例/全页外壳/错误隔离），新槽是重复建设；复用后自开页天然获得标签项语义与全页外壳，manifest 的 mounts 声明也就是既有词汇的扩展而非新槽位。
- **插件自行弹页**：输在"不能悄悄接管"——插件随时开页等于绕过用户控制权；入口由管理页显形、用户点开才成页，面板入口清单只留官方也服务同一条纪律。
- **无自开页的插件不做宿主呈现**：输在声明制配置需要默认归宿——manifest.settings 的渲染、身份事实与启停必须有宿主侧落点，否则声明制悬空；宿主呈现独立于自开页存在，两者覆盖"有页"与"无页"两类插件。

## Consequences

所得：呈现权分离清晰——管理呈现归宿主（声明制的落点），插件内容呈现归插件（自开页）；自开页零新机制（contentTab 复用）；首个消费方「正在播放」页补上全局播放的常驻控制面；插件面板去重复呈现，入口清单仅官方。

代价：插件要呈现全页内容须走"manifest 声明 + 具名导出 page"的固定形状（自由度换可控）；管理页承担 per-plugin 分区后信息密度上升；宿主词条页的既有实现撤除是返工成本（前案落地同轮即改——教训是"详情页"这类两层混用的词应在立项时拆清）。
