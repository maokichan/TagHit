# TagHit 架构与宿主（ARCHITECTURE）

> 架构活体文档：讲"东西放哪、为什么"。进度与下一步**只在 CONTEXT §三**跟踪，本文件不含状态。
> §一 是后端核心，§二 渲染层与宿主，§三 插件方向——读后端时可跳过 §二 之后。

## 一、后端核心（核心对渲染层/插件一无所知）

```
应用层 —— 用例编排（打标/浏览+投影/检索/维护/删除级联/扫描/来源根生命周期/内容读取），无状态
   │  调领域规则与端口
领域层 —— 实体与关系类型 · 纯规则（含路径规则）· 错误码；零依赖
端口   —— 契约第一公民 = 流动类型；动词薄按用例反推；查询下沉条件对象
适配器 —— memory（Store + 假文件系统，校准替身）· sqlite（驱动注入）· node（真文件系统）
```

- 存储契约全局约定：异步；实体写严格（NOT_FOUND/CONFLICT/INVALID）；关系写幂等；读宽松；事务 = 边界原子性、一致性编排在用例。
- 校准文化：无测试设施（code-first 校准理解）；memory 与 sqlite 跑同一场景，契约一致才绿。
- 工作区 ↔ 条目模型（来源根 → 路径节点 → 归属派生）与两阶段扫描已落地；扫描消失策略 keep/discard 可配；内容签名三采样点；图片固有尺寸扫描时从文件头零依赖解析（D15）。
- **扫描容错（D24）**：遍历遇到不可读路径不抛错，而是产出一条错误条目——扫描跳过其子树继续，并在摘要里报数；**文件级同规则**（单文件 `stat`/`hash`/`readHead` 失败只跳过该文件，计入 `filesUnreadable`）。**不可读的目录子树与文件一律退出消失判定**：读不到 ≠ 已消失，否则会误删节点行（连带条目退出视图）或把条目标为缺失。用户排除过的节点行在目录消失后保留（D27）。

## 二、渲染层与宿主（已落地）

### 官方功能组件名录（术语单点，2026-09-12）

**命名规则**：功能组件的名字 = 它管的**领域对象**（词见 GLOSSARY），**不另造别名**。
历史混乱：「路径管理」是自造词，词表从未定义它，却同时出现在组件名与文档里——现已统一为**来源根**。
（反例警戒：「文件路径管理」会与既有的**文件管理**组件相撞，禁用。）

| id | 名称 | 职责 | 呈现面 |
|---|---|---|---|
| `paths` | **来源根** | 来源根挂载/卸载、路径节点可见性、退役根与脱根条目去留 | 停靠面板（左）+ **全页** |
| `tags` | 标签 | 标签池与声明、按标签筛选 | 停靠面板（左） |
| `display` | 显示 | 显示面板块的容器（媒体类型/排序/布局/工作区信息） | 停靠面板（左） |
| `files` | 文件管理 | 对多选集做真实文件改名/移动/删除（只动磁盘，库随重扫收敛） | 停靠面板（左） |
| `info` | 媒体信息 | 当前选中条目的属性 | 停靠面板（右） |
| `plugins` | 插件 | 全页入口清单；三方分发落地后的管理面 | 停靠面板（右） |
| `globalSearch` | 全局搜索 | 跨工作区条目检索 | **全页** |
| `mediaTypeFilter` / `sort` / `layout` / `workspaceInfo` | 显示面板块 | 显示面板内的区块（媒体类型/排序/布局/工作区信息） | `displayPanel` 块 |
| `showTitles` / `keyboardMouse` | 设置项与行为 | 无面板：仅设置分区与行为注册 | `settings` |

**呈现面分工**（2026-09-12 裁决）：窄面板只做**就地轻量操作**（浏览、逐节点切换、只看某节点）；
**批量与去留处置归全页**（一键恢复全部可见、退役根与脱根条目的清理/恢复、扫描与结果概览）。
理由：窄面板空间有限且常驻，批量误触代价高（真实教训：为"只看一个节点"逐节点排除十余个目录）。

### 分层与落点

```
frontend/   渲染 UI（Vue3 + Pinia + router + Tailwind；经 typed 窄桥取数）
src/host/   主进程装配：SQLite 存储 + 真时钟/UUID + 逐端点注册用例 + 媒体字节协议；隔离窗口
契约单一事实源 = src/host/ipc.ts（渲染层仅 type-only 再导出，零运行时依赖）
```

- **边界纪律**：渲染层只认 uri，拿不到存储与裸 Node——一切走窄桥用例；错误按信封 code 转文案（D9）。
- **SQLite 驱动注入（D14）**：适配层只认最小同步接口；校准用 Node 内置驱动，Electron 主进程注入 better-sqlite3（ABI 匹配），内置驱动不进打包产物。
- **字节闸门（D15）**：媒体字节不进 IPC——经特权协议直取（白名单 = 各工作区来源根 + userData，路径段匹配，支持 Range/MIME）；文本走窄桥读端点（扩展名白名单 + 2MiB 上限）。视频缩略图（D16）是**派生小图**：渲染层抓帧 → 宿主落盘 → 按内容哈希回写，同内容共享一份。
- **无边框窗口（D17，术语标准）**：窗口形态称「**无边框窗口**」。标签栏兼任「**标题栏**」（空白处拖动/双击最大化，交互元素不拖拽），右上三键正式名「**窗口控制键**」。一词一义：「壳」专指插件语境的容器与展示层（§三），窗口语境不用「壳」。
- 数据流约定：渲染层持**视图状态**（工作区/勾选标签/排序/范围）；任何改动 = 改意图 → 窄桥调一次用例 → 失效重查；**不本地排序/过滤**（分页语义由存储一次完成）。
- **标签与导航语义（D26）**：**路由是标签的投影**——标签是唯一事实源。**激活已有标签用 replace，打开一个视图用 push**；标签切换若也写历史，所有切换会被串进同一条全局历史，侧键返回就变成在"标签访问日志"上乱退。守卫只在**路由没有对应标签**时回落活动标签，**绝不跳进另一个标签**。已知边界：标签尚无独立历史栈与多实例（真正的并行访问未支撑，见 TODO 的 2.0 级议题）。

### 渲染层插件机制（已全部落地，2026-09-07）

- **注册表 = 声明表**：可序列化声明（功能组件清单的形状，三方为磁盘 JSON）+ 实现绑定（构建期直连或运行期 loader，**与来源正交**；实现可**按呈现面**绑定：停靠面 / 全页面）。壳只查表渲染，不 import 具体组件。重复 id：官方抛错（开发期暴露），三方拒绝并报告。
- **标准容器**：所有功能组件的唯一渲染通道——槽查询 → 按呈现面选实现 → 惰性解析 → **壳级外壳**（停靠面板外壳 / 全页外壳 / 无外壳）→ 错误隔离 → 上下文注入。活动栏面板、显示面板块、内容区标签页共用。
  **容器归壳**（D22）：宽度/边框/滚动/角标归壳，功能组件只出内容——停靠面板外壳施加统一宽度变量，全页外壳给页头 + **居中的版心容器**（功能组件不自建侧栏，否则就是各自造窄边栏），且全页**不套窄面板**（功能组件按自己的功能各写全页；未绑定全页实现时给明确占位）。**全页入口唯一 = 面板右下角角标**。
  **两个呈现面共用一份数据与动作**（D22）：来源根组件给出的范式——状态与动作放一处（注入给子块），窄面板与全页面只差布局；跨实例动作广播失效重查。
- **错误隔离双线**：注册期（setup 抛错只废掉自己）+ 渲染期（槽级边界捕获）；官方组件走同一道边界。生命周期按条目配对（setup/dispose）。
- **命令注册表**：菜单项 = 命令 + 摆放元数据；when 是壳可求值的最小谓词（不加载实现即可过滤）；分组/排序/危险区沉底是壳的装配规则；菜单自绘，组件只声明"这块 DOM 是上下文目标"，事件拦截权归壳。**快捷键是同一张表的视图**（D23）：绑定只声明"组合键 → 命令 id"（可带设置项闸门与是否允许输入态触发），执行器把按键变成与右键菜单**同形**的调用上下文——因此"能绑什么"= "能注册什么命令"，权限清单不另立一套。
- **选择交互模型**（D23）：修饰键 → 选择意图的映射是壳级唯一实现（Shift = 区间 / Ctrl·Cmd = 切换 / 裸点击 = 单选），状态变更收口在条目 store；组件只转发原始事件，不自写修饰键分支。**点空白 = 未命中上下文目标**——与右键菜单共用同一份 DOM 契约，两处判定永不漂移。
- **服务面**：确认框/提示由壳统一渲染（组件不自起弹层）；manifest 的 surfaces 声明位就绪（v0 只声明不校验）。
- **配置仓**：按「功能组件 id + 键」持有并持久化（现为 localStorage，迁移宿主后键形状不变）；设置页直接读声明里的默认值。
- **HostApi 冻结面**：窄桥的冻结子集视图 + 独立版本号；三方只经此面。
- **同构验收桩**：一个官方组件已改成运行期装载，壳行为不变。**注册必须先于应用挂载**（挂载时读表，顺序错了活动栏就是空轨——踩过）。

## 三、前端与插件方向（已共识）

- **插件 = 提供程序所没有的能力**：UI 增强（面板/展示/命令）→ 渲染层贡献点；复杂运算/程序外能力（OCR、哈希、转码、扫描等）→ **主进程能力工具** + manifest 声明式权限。两层都经统一 **HostApi 门面**（窄桥冻结子集视图 + 独立版本号），核心保持对插件无知。
- **壳 = 插件容器与展示层**（不只 UI）：布局、标签页、面板拖拽/显隐都是壳/官方功能的行为。
- **贡献点 v0**：活动栏（左/右）· 内容区标签页 · 显示面板块 · 设置分区。**不做任意跨区停靠（完整 dock）**。
- 官方功能组件：居**左活动栏**（工具间切换/显隐）。三方插件：**左、右活动栏均可**，displayPanel 内可贡献块。
- 官方与三方插件：**注册机制同构**、信任/生命周期分层（官方静态可信；三方走动态加载、错误隔离、权限门、卸载清理）。性能用**惰性加载（激活条件 → 用时才 import）+ 事件仅推活跃订阅者**控制，同构不引入固定开销。
- **契约优先**：贡献点 + HostApi + 生命周期先立为稳定面（对插件作者是 API 契约）；先用**垂直切片**证明机制，再批量改造。

### 3.1 贡献点机制：选型理由与两个概念（2026-09-06 定稿）

**为什么是贡献点，而不是别的扩展方式**——三条既有裁决把选项收敛到唯一：

- 扩展方式候选与否决理由：
  - *自由 API 式*（暴露全局对象随便调/随便渲染）：插件绕开"改动 → 窄桥 → 失效重查"的数据流单通道，投影语义（声明裁剪/hiddenCount）会出现第二份实现。否。
  - *钩子/拦截式*（插件插进查询/扫描等核心流程）：让插件进入核心**控制流**；行为归属被稀释（流程在应用层、事务边界在用例），插件 bug 从"一块面板坏了"升级成"一次扫描/删除坏了"，还要定义顺序/await/抛错语义。否。
  - *中间件/管道式*：钩子变体，主流程（浏览/打标/扫描）不是管道形状。否。
  - *贡献点式*（VS Code 模型）：**壳声明槽位，插件只声明填充物**，壳按声明渲染，核心 import 图里永远没有插件。控制权反转，上述三条裁决全部保住。
- 贡献点的三个对应价值：① 服务"壳 = 插件容器与展示层"裁决——布局/标签页/显隐是壳的权力，插件只能往槽里放东西；② 数据流不破——贡献物拿数据走 HostApi 门面，与官方 UI 同一条窄桥；③ 信任可分层——声明式注册使官方静态/三方动态共用一张表，差异只收敛在"从哪来、信多少、何时加载"，且声明式 manifest 正是惰性加载的着力点。

**两个概念是同一机制的两面**，不是两套系统：

- **贡献点** = 壳侧的**槽**：活动栏（左/右）、内容区标签页、显示面板块、设置分区。回答"哪里可以插、插进来壳按什么规则渲染/排序/显隐"。槽是壳的权力清单（v0 不做任意 dock 就是这条清单的红线）。
- **功能组件** = 贡献侧的**插头**：可序列化声明（id / 名称 / 来源 / 挂载哪些槽 / 设置项 / 所需服务）+ 实现绑定（可分别绑停靠面与全页面）。回答"我声明自己是什么、挂哪些槽、有哪些配置项"。
- **官方组件没有任何特权路径**：与三方走同一注册表，槽只问注册表"这里有什么"，不 import 具体组件。真正的设计差异在三个**分层**维度（不在机制上）：
  1. 注册来源：官方 = 构建期直连 + 代码注册；三方 = 目录发现 + 声明文件 + 运行期装载（**发现/分发未接入**）；
  2. 信任与权限：官方全信；三方要权限门（所需服务/能力清单审查）+ 每贡献块错误隔离；
  3. 生命周期：官方与版本同生共死；三方有安装/启停/卸载，事件订阅可退订、状态可丢弃。
- **同构验收标准**：把任一官方功能组件改成动态加载后，壳行为完全不变（已有一个官方组件作此验收桩）。

**应用层不驻插件**（选型推论，单向铁律）：

- 三方代码不进主进程核心。"插件跑进应用层"技术上可行，但会同时击穿：信任边界（主进程直接摸 Store/fs）、事务语义（用例 = 单事务边界）、行为归属（删插件不应改变业务行为）、内部 API 冻结（用例签名是演进面，HostApi 才是冻结面）。
- 重运算（OCR/转码/哈希）= **主进程能力工具**：宿主调用、结果返回、不持有 Store、不进事务，经 manifest 权限闸门。
- 预留：未来若需"插件提供扫描期文件解析器/哈希器"，走**窄领域端口 + 独立进程**（Electron utilityProcess）实现，宿主拉起并注册，用例照常调端口——依赖仍只向内，插件 crash 不带崩宿主。不做流程钩子。

### 3.2 呈现面三分类与右键菜单标准化（2026-09-07 定稿）

插件 UI 落在壳里的方式收敛为**三类呈现面**，装配模型各不相同：

| 类别 | 例子 | 装配模型 |
|---|---|---|
| 停靠面 docked | 活动栏工具面板、显示面板块、设置分区 | 一块槽一个贡献者，经声明表静态装配 |
| 服务面 service | 弹窗/确认/通知 | 壳提供的受控服务（注入给组件），调用时临时起；**不是插槽** |
| 调用面 invoked | 右键菜单、（未来）命令面板/快捷键 | **多贡献者，调用瞬间按上下文现场聚合** |

右键菜单是调用面的样板，也是贡献点机制里第一个要求"声明式条件"的槽（停靠槽常驻，无"何时出现"语义）。标准化四要件（机制细节见 §二 命令注册表条目，裁决见 DECISIONS）：

1. **原子 = 命令**：菜单项不是容器成员，是命令 + 摆放元数据；命令面板/快捷键都是命令注册表的视图——一套注册表，不做三套平行系统。命令执行只经 HostApi 门面（改意图 → 窄桥 → 失效重查），数据流单通道不破；命令注册表同时是三方插件"可做的事"的权限清单底座。
2. **声明可序列化 + when 谓词**：命令 = 声明面（id / 名称 / 出现条件 / 分组 / 顺序，三方为磁盘 JSON）+ 执行（实现在实现侧）。壳必须**不加载实现即可过滤菜单**，故 when 是壳可求值的最小谓词（目标种类 / 字段相等 / 合取）；底线 = 相等与合取，不做表达式引擎。
3. **上下文目标注册**：组件不挂菜单监听，只声明"这块 DOM 是上下文目标"；壳根部统一拦截、就近取目标、构造调用上下文（目标 + 当前工作区 + **多选集**：目标已在多选内则整集带出，否则单目标）。事件拦截权归壳。
4. **装配规则归壳**：分组（导航/修改/危险）、分隔线、组内排序、溢出折叠全是壳的策略，插件只有分组与顺序两个建议字段；危险动作壳强制沉底 + 警示。菜单**自绘**（主题一致、可注入插件项、Esc/失焦关闭），不用原生。

三类呈现面的机制 2026-09-07 全部落地；三方插件的**发现/分发**（目录扫描、安装、启用管理）仍未接入，等分发形态裁决。
