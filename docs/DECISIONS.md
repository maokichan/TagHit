# TagHit 决策基线（DECISIONS）

分层、裁决与范围。概念见 GLOSSARY。

## 分层

```
渲染层 / 用户输入
   │
应用层（用例：流程编排，调领域规则与端口）     ← src/application（首批六用例已落地）
   │
领域层（实体类型 + 纯规则，无存储、无 IO）     ← src/domain
   │
端口（接口）──── 适配器（实现：SQLite/文件/…）
     ← src/ports（已落地）· src/adapters（内存先行，SQLite 规划中）
```

依赖只向内。行为在应用层；存储等实现位于领域层之外。

## 裁决

- 条目 item：全局唯一身份，不属任何工作区；去重是扫描行为（应用层）
- 工作区：索引容器；不拥有条目；条目可见性派生自来源路径树节点状态（节点只管其直接条目）
- 挂载：条目 × 标签（条目级）；取回条目返回全部标签
- 声明：工作区 × 标签的读取端投影事实，投影行为在应用层
- 标签关联：领域层只承认"标签间存在有向关联"，不解义；语义由使用方组织
- 作品：独立实体 + 有序成员 + 空条目标签锚点
- 组：全局扁平容器、标签可多属；语义在应用层
- 成员：作品 → 条目（有序，行记录带 position）；组 → 标签（无序）。两类行记录属领域类型
- 元数据：核心事实 + EAV 长尾，键注册表约束
- 渲染层：只认 uri，字节经主进程闸门
- 全局搜索：对全部工作区

## 领域层（src/domain）

`types.ts`（实体与关系行记录：挂载 ItemAttach / 标签关联 TagLink / 声明 Declaration / 成员 CollectionMember·GroupMember）· `rules.ts`（纯规则：命名与标签关联的不变量判定）· `errors.ts`

## 应用层用例（src/application）

- 已落地首批：打标/卸标（批量原子）· 浏览与声明投影 · 检索 · 组与作品维护 · 删除级联（单事务内反查清关联行再删实体）
- 规划中：收录扫描（路径遍历 + 条目级扫描）· 事件 · 实体生命周期命名/描述用例

## 端口与适配器（已落地 v0.2 起点；实现见 src/ports、src/adapters）

- 端口是**应用层对外部世界的需求清单**（被驱动接口）。契约的第一公民是**流动数据的类型**：实体与关系行记录在领域层，写输入 / 读条件对象 / 结果记录在端口文件；动词是这些类型的薄存取通道，按应用用例反推，不做业务判定。
- 存储端口：**单体 Store + 事务**，粒度不拆。`transaction` = 边界暴露的**原子性**（ACID），不支持嵌套；顶层单条读写可直呼。**一致性边界在应用层用例**：删除级联等多行一致由用例在同一事务内编排，端口不越界。
- 全局约定：异步边界（全 Promise）；实体写严格（NOT_FOUND / CONFLICT / INVALID）；关系写幂等（重复 add、移除缺失行 = no-op）；读宽松（条件引用不存在的 id 不报错）。
- **查询全部下沉到存储**：复杂查询用可扩展**条件对象**（ItemsQuery / TagsQuery）表达——不为每界面预造专用方法，也不预造通用查询引擎。
- 文件系统端口（walk / stat / readHead）；Clock / IdGen 注入。
- 适配器顺序：**内存先行**（`MemoryStore`，clone-on-write 模拟回滚，作开发/测试替身），后 SQLite（同一接口，v1 schema 待定）。
