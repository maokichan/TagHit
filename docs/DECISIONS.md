# TagHit 决策基线（DECISIONS）

分层、裁决与范围。概念见 GLOSSARY；架构/状态/渲染-核心分离见 ARCHITECTURE。

## 分层

```
渲染层/宿主（Electron：渲染 UI，主进程装配）   ← src/host + frontend/
   │
应用层（用例编排，调领域规则与端口）          ← src/application（已落地）
   │
领域层（类型 + 纯规则，无存储、无 IO）        ← src/domain
   │
端口（接口）──── 适配器（实现）              ← src/ports · src/adapters
```

依赖只向内。行为在应用层；存储/IO 实现位于领域层之外；核心对渲染层/插件无知。

## 裁决

- 条目 item：全局唯一，不属任何工作区；跨工作区去重是扫描行为
- 挂载：条目 × 标签（条目级）；取回条目返回全部标签
- 声明：工作区 × 标签，读取端投影事实；投影行为在应用层
- 标签关联：有向 tag→tag，领域不解义；语义由使用方组织（功能面不再考虑，见文末 parked）
- 作品：独立实体 + 有序成员 + 空条目标签锚点；组：扁平容器、标签可多属
- 成员：作品→条目（有序，position）；组→标签（无序）；行记录属领域类型
- 工作区 ↔ 条目：来源根（配置行，workspace 拥有根、不拥有条目）→ 路径节点（扫描产物，workspace × 目录路径，根=来源根；included/excluded 只作用该节点直接条目，不级联；扫描不覆盖既有 excluded）→ 归属（不落库，sourceUri 父目录 == 节点 dirPath 派生）
- 重叠挂载：条目全局共享；节点按工作区各建一份
- 扫描消失策略：keep（标 missing，默认）/ discard（删条目及关联），按扫描调用配置
- 内容签名：sha256 于头/中/尾三采样点；同内容必同签名
- 元数据：核心事实 + EAV 长尾；渲染层只认 uri，字节经主进程闸门；全局搜索对全部工作区

## 端口与适配器（已落地；契约见 src/ports/store.ts 头部）

- 端口是应用层对宿主的需求清单。第一公民 = **流动数据的类型**（领域行记录 + 端口写输入/条件对象/结果）；动词薄、按用例反推、不做业务判定。
- Store：单体 + 事务（transaction = 边界原子性，不支持嵌套；一致性边界在用例）。全局约定：异步；实体写严格（NOT_FOUND/CONFLICT/INVALID）；关系写幂等；读宽松。
- 查询下沉到存储：ItemsQuery/TagsQuery 可扩展条件对象（不预造方法、不做通用查询引擎）。
- 适配器一致性：memory 与 sqlite 跑同一份场景（scripts/s32、s33）。SQLite 外键会暴露排序/删除次序依赖（例：删作品先删 collection 行再删锚）。

## 渲染层与插件（裁决基线；选型论证与机制细节见 ARCHITECTURE §3）

- 壳 = 插件的**容器与展示层**；官方功能组件与三方插件**注册机制同构**，差异只收敛在信任/生命周期分层（官方静态全信；三方动态装载、权限门、错误隔离、启停卸载）。同构验收：任一官方组件改动态加载后壳行为不变（workspaceInfo 已作验收桩）。
- 贡献点清单：`activityBar:left/right` · `displayPanel` 块 · `settings` 分区 · `contentTab` 内容标签页；**不做任意跨区停靠（完整 dock）**。官方组件居左活动栏；三方左右均可、displayPanel 可贡献块。
- 扩展机制 = 贡献点（壳声明槽、插件声明填充、壳渲染），否决自由 API/钩子/管道（理由见 ARCHITECTURE §3.1：保住数据流单通道与行为单一归属）。
- 呈现面三分类：停靠面（槽）/ 服务面（壳的受控服务，非插槽）/ 调用面（多贡献者调用瞬间按上下文聚合）；插件 UI 只经这三类落到壳里。
- 注册表 = 声明表：可序列化 FeatureManifest + 实现绑定 FeatureImpl（direct | async，**与 source 正交**）；错误隔离双线（setup try/catch + 槽渲染 FeatureBoundary），官方组件同边界；生命周期 per-entry（setup/dispose 配对 + unregisterFeature）；contributed 重复 id 拒绝并报告，不炸注册表。
- 命令为原子：菜单项 = 命令 + 摆放元数据，命令面板/快捷键是同一注册表的视图；`run(ctx)` 只经 HostApi，命令注册表即三方权限清单底座。when 为壳可求值的最小可序列化谓词（相等/合取，不加载实现即可过滤），防表达式引擎蔓延。事件拦截权与装配规则（分组/排序/溢出/危险区沉底）归壳，菜单自绘不用原生。
- 服务面权力：dialog/toast 是壳的受控服务（ServiceHost 统一渲染）；功能组件禁止自起弹层；manifest.surfaces 声明所需服务 = 权限清单渲染侧雏形（v0 仅声明不校验）。
- settings 归属：SettingSchema.key = 组件内 key；存储键 = `featureId:key`，由壳 config 仓统一持有并持久化（localStorage 起步，迁宿主 config 端点时键形状不变）；ui store 只保留壳自身外观。
- contentTab 状态归属：壳持标签项（featureId/title/激活），组件自持内容状态、经 HostApi 取数；关闭即销毁；同一 feature 单实例；路由 `/feature/:featureId` 是标签的投影。
- HostApi 冻结面：HostApi = 窄桥的冻结子集视图 + HOST_API_VERSION（独立演进，破坏性变更升 major）；官方可用全量窄桥（同版本发布），contributed 只经 HostApi；命令与权限清单以此为底座。
- 插件能力分层：UI 增强 → 渲染层贡献点；复杂运算/程序外能力 → **主进程能力工具 + manifest 声明式权限**；应用层不驻插件，未来扫描期解析器走窄端口 + 独立进程（utilityProcess），不做流程钩子。
- 渲染层数据流：视图状态在渲染层；改动 → 窄桥用例 → 失效重查；不本地排序/过滤。
- 视频缩略图（D16）：视频缩略图 = **派生小图**，走专用窄桥 `thumbnail.save`（canvas 抓帧 JPEG base64，≤2MiB）→ 宿主落盘 `{userData}/thumbnails/{contentHash}.jpg` + 应用层 `recordThumbnail` 按 contentHash 回写 previewUri/width/height（同内容多条目共享一份；查询下沉 `ItemsQuery.contentHash`）。**不做 ffprobe/ffmpeg 依赖**——尺寸在抓帧时经 video 元素顺带取得。渲染层懒生成 + 幂等（pending/failed + 落库复用）。
- 多选与批量（D16）：`MenuContext.selection` = 调用瞬间的操作对象集（target 已入多选集 → 整集带出，否则 = 单 target）；批量打标经**受控服务弹层**（服务面 batchTag，标签多选 + 打/卸两钮）→ 应用层 `tagItems/untagItems`（单事务）→ 失效重查。**批量不新造端口写方法**：事务内循环复用 attach/detach（与级联删除同款模式）。多选交互：Ctrl/Cmd+单击 toggle、单选单击即聚合。

| D18 | 文件身份与来源根树/文件管理 | **扫描认领**：新路径与既有缺失条目同内容签名（且旧路径确已消失）→ 原条目改写来源并恢复，id 与标签/作品成员随行——**应用外**的移动/改名经重扫收敛不丢标签。**文件操作闸门**：移动/删除只收来源根之下路径（路径段匹配，与字节闸门同规则）；删除进系统回收站，不可恢复删除不进用例面；来源根目录本身不进移动/删除面。**应用内操作直改库（免扫）**：移动/改名在同一事务内按同一条重定基规则（domain rebasePath）改写条目来源与节点行——保 id 保标签、title 随文件名、excluded 意图随行、目的地祖先节点链补齐（可见性 = 直接父节点存在且 included，是查询时派生的：新目录没有节点行会让条目当场脱视图）；**删除 = 条目记录级联清除**（用户裁决：应用内删除即删除，不标缺失——标签是可再生信息，文件本身在系统回收站可寻回，反悔后重扫按新条目收录）。**路径归一化在边界执行**：反斜杠→正斜杠、去尾分隔符、解析 `.`/`..`（安全项：闸门按文本前缀匹配时相对段可穿透）；用户输入与原生选择器的混合分隔符不得产生双身份节点。**原生目录选择是唯一对话框端点**。**来源根树**：每根一个目录树容器，树形由路径前缀派生；可见性逐节点可切换、**不级联**，Shift+点击 = 子树批量入口。**渲染进程崩溃自恢复**：记日志 + 重载（上限 3 次防循环）。其中"角标打开全页"的形态已被 D22 取代（真全页，不再复用窄面板）。**移动认领的边界**：内容签名在此充当**移动认领键**（另有 D16 的缩略图共享键）：三采样签名不承诺对整文件全局唯一，头/中/尾三段全同的两个不同文件会被当作同一内容——认领可能错位、缩略图串用；这是与"全文件哈希成本"的折中，已知并接受（契约注释已写明，见 ports/filesystem.ts） |
| D19 | 浏览派生条件下沉与分页 | **可见性 = 查询条件，不是"取回来再筛"**：直接节点状态派生下沉到存储翻译，排序/分页/总数一律作用于结果集——否则可见条目数会随排序键与方向变化。**路径纯规则上移领域层**，应用层与适配器同源——SQL 侧是它的等价译文，等价性由校准双跑逐一致比对；**归属仍不落库**。**目录范围条件收紧为路径段匹配**（`D:/a` 不误命中 `D:/ab/x`），并复用为「只看某节点」的视图范围（渲染层视图状态，不改可见性）。**计数可信**：总数与分页由存储一次给出，渲染层不拿"已渲染条数"当总数。批量读的绑定参数按块收敛（大库全量读不撞参数上限）。**摘要并集计数**：摘要类统计的"根下总数"用 `underAnyDir` **并集一次计数**，不逐根求和——挂载侧允许来源根嵌套/重叠，逐根求和会把重叠部分的条目重复计入（nodeMissing 因此虚高） |
| D20 | 来源根生命周期：退役根与脱根条目 | **卸载留凭据**：卸载来源根 = 删来源根行与其节点树（条目不动），并落一行**退役根**记录（路径 + 时间）；条目数按前缀实时统计、不冗余存储。挂载同一路径即清除记录（挂载 = 恢复归属，节点树随重扫重建）。**脱根条目**（有来源但无任何来源根覆盖）分两段报告：退役根之下的（有记录，给精确路径/时间/条目数）与无记录的历史残留（按父目录聚合）；判定用否定式路径段条件下沉存储，不把全库条目捞进内存。**清理安全性由构造保证**：候选集恒为"当前脱根条目"，传来源根路径也删不到在根下的条目；磁盘文件不动 |
| D21 | 历史路径双身份一次性修复 | 归一化只在边界执行（D18），更早写入的来源可能保留反斜杠；重扫写正斜杠新行 → 同一文件两条条目，旧行永远匹配不到路径节点 → **永久不可见且白占查询窗口**。修复为**无损、幂等**的一次性用例：有孪生行 → 旧行标签与作品成员迁到保留行（重扫产物是当前事实）、补齐其缺失的派生元数据后删旧行；无孪生行 → 原地归一化（id 与标签不变）。宿主启动时执行一次，重跑为空操作 |
| D22 | 容器归壳：停靠面板外壳与全页呈现面 | **外壳由呈现面决定、归壳所有**，功能组件只出内容、不自绘宽度与边框（容器在组件侧，各面板宽度必然管不齐）：停靠面 → 面板外壳（统一宽度 + 边框 + 滚动 + 角标）；全页面 → 全页外壳（页头 + 居中版心）；显示面板块与设置分区 → 无外壳。**呈现面显式声明**：声明了内容标签页槽 = 该组件提供全页；实现可**按呈现面分别绑定**（停靠面 / 全页面，同一注册条目，不是两套注册）。**全页不复用窄面板**（用户裁决）：内容型功能的实现本身就是全页内容，其余组件各自写全页；未绑定全页实现时给明确占位，**不回落窄面板**。**同一功能的两个呈现面共用一份数据与动作**（状态与动作注入子块，只差布局），首个落地在来源根组件 |

| D24 | 扫描对不可读目录的容错 | **单点故障不得让整次扫描失败**：遍历遇到不可读路径（根不存在、权限、IO）产出错误条目而非抛错，扫描跳过其子树继续，并在摘要报数。**关键推论：不可读子树整体退出消失判定**——读不到 ≠ 已消失，否则会删掉该子树的节点行（连带条目退出视图）或把条目标为缺失，这比"少扫一点"严重得多（节点行与条目状态一律不动，等下次扫描再说）。校准用内存文件系统加故障注入断言该行为。**文件级同规则**：单文件 `stat`/`hash`/`readHead` 失败（权限/IO）同样只跳过该文件并计入摘要（`filesUnreadable`），既不建/更新条目也不参与消失判定；遍历与采集之间已消失的文件另当别论——那是真消失，照常交给消失判定按 keep/discard 处理 |
