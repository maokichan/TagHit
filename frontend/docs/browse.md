# 浏览与网格（browse & grid）

> 数据面机制（可见性下沉/计数可信/小图通道）见 `docs/ARCHITECTURE.md` 与 `docs/GLOSSARY.md`；
> 框选/拖出的调用面契约见 ARCHITECTURE §二「四个调用面视图」。本文收筛选语义与交互细节。

## 格式筛选（媒体类别：mediaTypeFilter 块）

- **类别不是数据库事实**：条目只存文件名，媒体类别由扩展名**展示推导**（viewModel），
  数据库不增列；筛选 = **扩展名集合下推**（`ItemsQuery.extensions`，判定基准 = 领域
  `rules.extensionOf`，sqlite 用 `LOWER(title) LIKE` 等价译文，s35 逐一致比对；仅命中 file
  条目；空数组 = 恒不命中）。
- **"类别里有什么格式"用户说了算**：类别 → 扩展名映射是本块的设置项（config 仓持久化，
  启动时经 setup 钩子应用、变更即生效），默认表即内置表；宿主与存储只见过扩展名、不知道类别语义。
- **呈现**：块面只列**当前视图条件下真实存在**的类别（每类别一次 limit:1 的 browse 取 total，
  视图条件照常生效、唯独不含格式自身），计数为 0 的类别不出现；激活中的筛选计数归零仍保持
  可见（不然无法取消）。
- **顺序上下文携带**：ItemContext 增 `extensions`，路由 query 键 `ext`——详情页翻页沿的就是
  筛选后的序列。
- 已知边界：映射变更后已加载的条目视图要到下次查询才按新映射重推导（变更即重查未做，
  见根 `TODO.md`「前后端边界」）。

## 无标签筛选（untagged 块）

- 语义即 `withoutAnyTag`（排除语法见 `docs/tags.md`「检索语法」）；呈现与格式筛选同款
  （只列真实存在者、归零保持可见）。

## 浏览手感

- **返回工作区保滚动位置与分页深度**；**Ctrl+Tab 循环切换标签页**。
- 网格/瀑布流一律优先派生小图（ARCHITECTURE 缩略图条）；瀑布流比例只取实测值并钳制。

## 框选（marquee）行为细节

- **只在空白处起手**（与右键菜单/拖出共用同一份 DOM 契约判"空白"），**超过 4px 才算框选**——
  裸点击仍是"点空白清空选择"，手抖不该变成一次框选；**意图在按下瞬间定型**（中途按/松 Ctrl
  不改语义）。
- **裸拖 = 替换选择，Ctrl/Cmd+拖 = 翻转命中条目**（与 Ctrl+点击同一语义，第二框可撤误框）；
  Shift 不另立语义（它已是"区间"的修饰键，框选本身就是连续区间）。
- 纯几何（矩形归一、相交、命中、阈值）单列 `features/marquee.ts` 供 Vitest 直跑。
- **框选后的那次 click 必须抑制**（否则刚框完就被"点空白"清空）：标志位由**下一次 mousedown
  复位**，不做"消费一次"——鼠标在容器外抬起时那次 click 根本不出现，消费式标志会留下假的
  抑制态（表现为"点空白清不掉选择"）。
- 已知边界：只命中**已渲染**卡片（虚拟化之外不在屏幕上）、无拖到边缘自动滚动——待办在根
  `TODO.md`「壳/键鼠」条。
